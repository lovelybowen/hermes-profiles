# 根因分析

## 五问法

针对每个症状持续追问“为什么”，直到找到系统或流程层面的根本原因：

1. **症状：** 哪里出了问题？
2. **直接原因：** 哪个事件触发了故障？
3. **促成原因：** 哪些条件让触发事件成为可能？
4. **系统性原因：** 哪个流程或设计缺口允许这些条件存在？
5. **根因：** 要防止复发，必须改变什么？

## 常见根因类别

| 类别 | 示例 |
|----------|---------|
| **逻辑错误** | 条件不正确、变量错误、差一错误 |
| **竞态条件** | 共享状态未受保护、顺序假设错误 |
| **配置** | 设置错误、缺少环境变量、路由错误 |
| **数据假设** | 意外的 null、类型错误、输入格式异常 |
| **超时/延迟** | 未设置超时、等待时间不足、阻塞调用 |
| **资源耗尽** | 内存泄漏、连接池耗尽、磁盘已满 |
| **版本不匹配** | 依赖版本不兼容、API 契约漂移 |

## 验证

识别根因后，通过以下步骤验证：
1. 创建能够证明根因的最小复现。
2. 应用修复，并确认复现不再失败。
3. 检查修复没有破坏相关功能。
