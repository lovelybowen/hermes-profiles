# 测试策略设计

## 测试金字塔

```
        ╱╲
       ╱ E2E ╲         少量 - 关键用户旅程
      ╱────────╲
     ╱          ╲
    ╱ Integration ╲     一些 - 契约测试、API 测试、服务边界
   ╱────────────────╲
  ╱                  ╲
 ╱   Unit / Component ╲    大量 - 隔离、快速、确定性
╱────────────────────────╲
```

| 层级 | 速度 | 维护成本 | 可发现的问题 |
|-------|-------|-----------------|-----------------|
| 单元 | 毫秒 | 低 | 逻辑错误、边界情况、不变量 |
| 集成 | 秒 | 中 | 契约不匹配、数据流错误 |
| E2E | 分钟 | 高 | 系统行为、用户可见的回归 |

## 基于风险的优先级划分

| 风险等级 | 所需测试覆盖 | 示例 |
|------------|----------------------|---------|
| 严重（P0） | 100% - 每条路径、每个边界情况 | 支付处理、认证、数据完整性 |
| 高（P1） | 90% 以上 - 所有正常路径、已知失败模式 | 核心业务逻辑、API 契约 |
| 中（P2） | 70% 以上 - 正常路径、常见失败模式 | 次要功能、非关键 API |
| 低（P3） | 仅冒烟测试 | UI 润色、可选功能、调试工具 |

## 按项目类型选择测试

| 项目类型 | 建议测试组合 |
|-------------|---------------------|
| 库 / SDK | 80% 单元、15% 集成、5% E2E |
| Web API | 40% 单元、40% 集成、20% E2E |
| Web 应用 | 30% 单元、40% 集成、30% E2E |
| CLI 工具 | 60% 单元、30% 集成（输出比较）、10% E2E |
| 数据管线 | 50% 单元、40% 集成（数据流）、10% E2E |
