# 群体验证质量门

reviewer 角色作为看板群体的质量门。本参考资料定义如何评估工作者输出，以及如何决定通过或阻断。

## Reviewer 的职责

reviewer 位于并行工作者与综合者之间，充当质量门。你不生成实现输出，而是评估它；你不修复问题，而是标记问题。

你的职责是回答一个问题：**工作者的集体输出是否满足群体简报？**如果满足，则附摘要通过；否则附具体整改指引阻断。

## The Gate Decision

### 通过 - `{"gate": "pass"}`
所有标准均满足。应包含产出摘要以及综合者需要了解的注意事项。

```
## 结论：通过

## 摘要
[工作者总体产出的内容]

## 注意事项
[任何限制、开放问题或综合者需区别处理的领域]

## Gate
{"gate": "pass"}
```

### 阻断 - `{"gate": "block", "reason": "..."}`
标准未满足。应包含准确缺口以及解除阻断需要发生什么。

```
## 结论：已阻断

## 缺口
[缺少或错误的内容，必须具体]

## 证据
[引用简报要求及不满足要求的工作者输出]

## 解除阻断所需内容
[准确说明需要改变什么，例如“工作者需要研究 X”，而不是“做得更好”]

## Gate
{"gate": "block", "reason": "..."}
```

## 评估标准

评估每份工作者输出时，检查：

| 标准 | 检查内容 | 失败情形 |
|-----------|--------------|---------|
| **完整性** | 输出是否完成简报中分配的任务？ | 覆盖不全、遗漏要求 |
| **准确性** | 主张是否有证据支持？是否引用来源？ | 无依据主张、事实错误 |
| **相关性** | 输出是否服务于群体目标？ | 离题、范围漂移 |
| **连贯性** | 输出作为独立交付物是否合理？ | 混乱、矛盾或推理不完整 |
| **可执行性** | 综合者能否使用该输出？ | 需要大量返工才有用 |

## 阻断协议

### 何时阻断（而不是吹毛求疵）

只有输出无法按原样使用时才阻断。如果输出可用但不完美，应附注意事项通过。阻断成本高，会延迟整个群体并重新调度工作者。

**出现以下情况时阻断：**
- 未完成必需任务。
- 输出包含会继续传播的事实错误。
- 输出误解简报。
- 输出严重不完整。

**出现以下情况时不要阻断：**
- 输出足够但不够优雅。
- 存在综合者可处理的轻微遗漏。
- 方法与你会采用的方法不同。
- 输出只需文字编辑，而非重新研究。

### 如何有效阻断

好的阻断应向工作者准确说明修复问题所需内容，无需重新解释简报：

- **不要：**“这不够深入，请改进。”
- **应当：**“简报要求至少三项来源的支持性证据。本输出只引用了一项。工作者需要补充[具体主题 X]和[具体主题 Y]的研究。”

### 升级处理

如果工作者第二次尝试仍未通过质量门，问题可能在简报而非工作者。应标记这种可能：“该任务两次尝试均未通过质量门。简报可能模糊，或者任务可能错误地分配给该角色。”

## 向综合者交接

通过质量门时，应组织输出，使综合者能够直接使用：

1. **发现了什么：**所有工作者的汇总发现。
2. **缺少什么：**综合者应补齐或标记的缺口。
3. **什么不确定：**综合者应谨慎处理的低置信度发现。
4. **建议什么：**基于证据给综合者的方向。
