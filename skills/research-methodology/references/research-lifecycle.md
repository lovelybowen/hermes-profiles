# 研究生命周期

专业研究工作的完整过程，从形成问题到交付报告。

## 阶段 1：范围 - 界定研究问题

在收集任何来源前，明确要寻找什么以及原因。

### 研究简报

每个研究项目都从一份简报开始。继续之前先加载并填写 `assets/research-brief.md`。简报应回答：

- **核心问题：**究竟要弄清什么？将其表述为一个单一、可证伪的问题。
- **范围边界：**哪些纳入、哪些排除。在搜索前定义纳入和排除标准。
- **所需深度：**快速扫描（2 至 3 个来源了解全貌）、全面研究（穷尽一个窄问题）或深入研究（从多个角度研究复杂问题）。
- **决策上下文：**谁需要这些信息，会据此做什么？产品决策需要的证据不同于研究论文。

### 问题类型

| 问题类型 | 寻找的内容 | 示例 |
|--------------|------------------------|---------|
| **描述型** | 正在发生什么？ | “消费级 GPU 上本地 LLM 推理使用哪些架构？” |
| **比较型** | X 与 Y 相比如何？ | “Qwen3.6 与 Gemma 4 在工具调用方面相比如何？” |
| **因果型** | 什么驱动 X？ | “为什么 MoE 模型在大批量下推理延迟更低？” |
| **评估型** | X 是否有效？ | “有哪些证据表明 RAG 比零样本推理更准确？” |
| **缺口发现型** | 什么尚不清楚？ | “神经形态边缘部署有哪些内容尚未发表？” |

### 纳入与排除标准

搜索前定义：
- **日期范围：**来源必须有多新？
- **来源类型：**同行评审、行业报告、博客文章还是文档？
- **权威阈值：**来源满足什么条件才足够可信？
- **语言：**仅英语还是包含其他语言？
- **去重规则：**多个来源报告同一发现时，按一个还是多个来源计数？

## 阶段 2：收集 - 系统化发现来源

### 搜索策略

1. **先宽后窄。**首个查询应足以绘制领域全貌，后续查询根据已发现内容逐步收窄。
2. **使用多个搜索角度。**不要依赖单一查询。按关键词、作者或机构、工具名称、问题陈述和相关概念进行搜索。
3. **引用链追踪。**针对每个有价值的来源：
   - **向后：**跟随引用和参考文献，找到作者依赖的来源。
   - **向前：**搜索引用该来源的论文，例如 Google Scholar 的“被引用”。
4. **来源多样性。**不要只依赖一种来源，应混合使用：
   - 一手研究（论文、技术报告）。
   - 灰色文献（博客文章、文档、论坛讨论）。
   - 专家评论（行业分析、会议演讲）。
   - 实证数据（基准测试、数据集、可复现实验）。

### 记录每个发现的来源

| 字段 | 用途 |
|-------|---------|
| 标题与 URL | 方便再次找到它 |
| 作者或来源 | 评估可信度 |
| 日期 | 检查时效性 |
| 关键主张 | 与问题有关的陈述 |
| 支持性证据 | 支撑主张的内容 |
| 缺口或局限 | 未说明的内容 |
| 与简报的关联 | 如何回答研究问题 |

## 阶段 6：报告 - 组织发现

研究简报应具有以下结构，见 `assets/research-brief.md`：

1. **管理摘要：**用一段话回答研究问题。
2. **关键发现：**3 至 5 项附带置信度的综合发现。
3. **证据表：**将来源映射到发现。
4. **置信度评估：**哪些稳固、哪些不确定、哪些缺失。
5. **开放问题：**仍然不知道的内容。
6. **来源：**包含 URL 的完整引用。

## 决策上下文

不同需求对应不同研究深度：

| 上下文 | 深度 | 来源 | 时间 |
|---------|-------|---------|------|
| 用于决策的快速回答 | 扫描 | 2 至 3 个定向来源 | 分钟级 |
| 用于对话的简报 | 轻量 | 5 至 8 个来源、2 个角度 | 1 小时 |
| 支持一项建议 | 中等 | 10 至 15 个来源、3 个以上角度 | 半天 |
| 作为出版物基础 | 深入 | 20 个以上来源、穷尽式 | 数天 |
