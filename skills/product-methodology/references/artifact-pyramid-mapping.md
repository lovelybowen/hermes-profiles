# 产物金字塔映射 — 产品管理

每次产品任务产出一个位于绝对文件系统路径的产物金字塔。本文档把每个方法论和产物类型映射到其金字塔层级。

## 层级结构

```
┌──────────────┐
│ L1（摘要）   │ ← 高管和干系人停在这层
├──────────────┤
│ L2（分析）   │ ← 工程师和设计师在这层工作
├──────────────┤
│ L3（档案）   │ ← 参考层——按需拉取
└──────────────┘
```

## 完整映射

### L1（摘要）

放在这里的是一段话答案。适合高管简报、干系人更新或 spec 首页。

| 产物 | 内容 | 受众 |
|----------|-----------------|---------|
| 电梯陈述 | 一段话产品描述：谁、什么、为什么、差异点 | 所有人 |
| 愿景陈述 | 1-2 段北极星——成功长什么样 | 干系人、团队 |
| RICE 摘要表 | 排好序的优先级：功能名、RICE 分、一行理由 | 干系人、PM |
| 干系人简报 | 以建议开头的简洁更新：我们在做什么、为什么 | 高管 |
| OST 根视图 | 核心机会——一切追溯到的那一个客户需要 | 全团队 |
| 决策登记（摘要） | 活跃决策、状态和一行上下文 | 干系人 |
| MoSCoW 概览 | 当前时间盒的进/出——每项一行 | 团队、干系人 |

**格式：**`/01-summary.md` 单个 markdown 文件。

### L2（分析）

放在这里的是推理、需求和范围定义。工程师和设计师读这层来构建。

| 产物 | 内容 | 受众 |
|----------|-----------------|---------|
| 问题陈述 | 2-4 段，具体的用户语言，不含方案 | 工程师、设计师 |
| 用户故事 | 按能力域组织，每条含角色/行动/结果 | 工程师 |
| 核心概念 | 有边界的领域名词——每个一句话定义 | 全团队 |
| 原则 | 3-8 条约束每个决策的设计一致性规则 | 工程师、设计师 |
| PRD 第 2-9 节 | 问题陈述到成功标准——结构化 spec | 全团队 |
| Spec 模板 | 完整 spec：范围、边界情况、约束、风险 | 工程师、设计师 |
| MoSCoW 明细 | 每个条目的分类及一行归因理由 | 工程师、PM |
| 决策日志 | 带背景、选项、理由的决策记录 | 团队、未来的 PM |
| OST 机会层 | 每个机会的证据、假设和潜在方案 | PM、设计师 |
| 边界情况登记 | 已知边界情况及处理状态 | 工程师、QA |
| 风险表 | 风险、可能性、影响、缓解 | 工程师、PM |

**格式：**`/02-analysis/` 下多个 markdown 文件。每个能力域或产物类型一个文件。每个 L2 文件向下链接到相关 L3 档案。

### L3（档案）

放在这里的是原始材料。来源数据、转录、详细分析。默认没人读这层——它存在的目的是验证主张和按需深入。

| 产物 | 内容 | 何时消费 |
|----------|-----------------|---------------|
| 完整 PRD | 全部 13 节，含 UX 草图、生态图、完整风险分析 | 需要正式签署时 |
| 客户访谈转录 | 发现式访谈的原始转录或详细笔记 | 挑战「用户要什么」的假设时 |
| 竞品深潜 | 每个竞品方案的详细分析 | 捍卫战略选择时 |
| RICE 打分输入 | 触达/影响/信心/成本数值及其来源 | 优先级被质疑时 |
| OST 叶节点 | 单个实验、其假设与结果 | 评估继续还是转向时 |
| RTM（需求追溯矩阵） | 需求到测试用例的正式映射 | 受监管环境 |
| 问卷原始数据 | 未处理的问卷回答 | 核验定量主张时 |
| 市场规模测算表 | 市场规模估算背后的假设 | 捍卫 TAM/SAM/SOM 数字时 |
| 干系人访谈笔记 | 单个干系人的需要与关切 | 平衡冲突的优先级时 |

**格式：**`/03-dossiers/` 下的文件。按来源或主题组织。每份档案自包含、可独立消费。

## 设计原则

1. **每层可独立消费。**高管只读 L1 就有全部所需。工程师读 L2 就有需求。默认没人读 L3。
2. **L1 链接到 L2。**摘要中的每个主张指向证实它的分析文件——通过 SOURCES 节。
3. **L2 链接到 L3。**每个依赖来源数据的分析文件链接到相关档案——通过 SOURCES 节。
4. **路径即契约。**对任何调用方的响应是 `00-index.md` 的绝对路径。调用方自己导航。无自然语言交接。

## SOURCES 格式

每层的每个文件底部都带：

```
SOURCES (LAYER {N} NAVIGATION)
path/to/file.md
-> 一行描述，回答「往下读会发现什么？」
path/to/another-file.md
-> 另一个维度或支撑证据
```

路径相对文件所在位置。描述回答每个下游 Agent 加载前都会问的问题：**往下读会发现什么？**

## 生产检查清单（门禁审计）

以路径响应前跑一遍：

- [ ] `00-index.md` 存在且含映射每层的导航表
- [ ] `01-summary/index.md` 的 SOURCES 链接到每个 L2 文件
- [ ] 每个 L2 分析文件的 SOURCES 链接到相关 L3 档案——**零孤儿文件**
- [ ] 每个 L3 档案有来源署名元数据（URL、抓取日期、作者、标题）
- [ ] 所有 SOURCES 路径从其文件位置可解析
- [ ] 每层可独立消费（读者停在任何一层都有所需内容）
- [ ] 响应将只是 `00-index.md` 的绝对路径——无散文、无摘要、无对话

任何复选框未勾都回去修好再响应。分析文件缺 SOURCES 是硬门禁失败——该文件尚未就绪交接。
