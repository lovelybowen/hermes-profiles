# 流程设计

用于理解、记录和改进业务流程的框架。流程设计是卓越运营的基础——无法改进尚未完成映射的流程。

## 价值流图（VSM）

一种精益管理技术，用于分析向客户交付产品或服务所需的物料流和信息流。

### 标准 VSM 元素

| 符号 | 名称 | 含义 |
|--------|------|---------|
| □ | 流程框 | 一个流程步骤（部门、系统、人员） |
| ▼ | 库存 | 步骤之间的在制品 |
| → | 推动箭头 | 物料在没有拉动信号的情况下移动 |
| ☰ | 信息流 | 沟通（人工或电子） |
| ⚡ | 改善爆发点 | 已识别的改进机会 |
| ⏰ | 时间线 | 增值时间与非增值时间 |

### 构建当前状态 VSM

1. **定义产品/服务。**正在映射的具体产品、订单或请求是什么？
2. **走查流程。**亲自跟随工作从开始走到结束。不要凭记忆映射。
3. **映射流程步骤。**每个主要步骤都是一个流程框。包括等待状态和交接。
4. **收集每个步骤的数据：**
   - 周期时间（完成该步骤所需时间）
   - 换型时间（在不同类型之间切换所需时间）
   - 可用时间/可靠性
   - 一次通过率（第一次就正确完成的工作占比）
   - 操作人员数量
5. **映射信息流。**每个步骤如何知道该做什么？电子邮件？系统？口头通知？
6. **添加时间线。**计算增值时间与总前置时间。

### 增值与非增值

| 类别 | 定义 | 示例 |
|----------|-----------|----------|
| **增值（VA）** | 以客户关心且愿意付费的方式改变产品/服务 | 制造、代码开发、客户咨询 |
| **业务非增值（BNVA）** | 法规或业务政策要求，但客户不认为有价值 | 合规检查、报告、审批 |
| **非增值（NVA）** | 纯粹浪费。客户不会为此付费。 | 返工、等待、交接、不必要的步骤 |

### 效率指标

```
流程周期效率 = 总增值时间 / 总前置时间
```

| 效率 | 分类 |
|------------|---------------|
| > 25% | 优秀。精益流程。 |
| 10-25% | 良好。仍有改进空间。 |
| 5-10% | 多数组织的典型水平。存在大量浪费。 |
| < 5% | 高浪费环境。存在重大机会。 |

## BPMN（业务流程模型与标记法）

一种用于流程建模的标准化标记法。需要正式、无歧义的流程文档时使用 BPMN。

### 核心元素

| 元素 | 标记 | 含义 |
|---------|----------|---------|
| 事件 | 圆形 | 发生的事情（开始、结束、计时器、消息） |
| 活动 | 圆角矩形 | 执行的工作（任务、子流程） |
| 网关 | 菱形 | 决策点（XOR、AND、OR） |
| 顺序流 | 实线箭头 | 活动顺序 |
| 消息流 | 虚线箭头 | 参与者之间的沟通 |
| 池 | 大矩形 | 流程中的一个参与者 |
| 泳道 | 池内的嵌套区域 | 参与者内部的角色或部门 |

### 网关类型

| 网关 | 逻辑 | 视觉标记 | 使用场景 |
|---------|-------|--------|----------|
| **XOR（排他）** | 恰好一条路径 | 标准菱形 | 是/否决策、路由 |
| **AND（并行）** | 执行所有路径 | 带 + 的菱形 | 任务可同时发生 |
| **OR（包容）** | 一条或多条路径 | 带 O 的菱形 | 多个条件可能同时为真 |

## 瓶颈分析

在任何流程中，最慢的步骤决定整个系统的吞吐量。瓶颈分析用于识别该步骤。

### 约束理论（Goldratt）

1. **识别**约束（瓶颈）。即容量最小或周期时间最长的步骤。
2. **充分利用**约束。最大化瓶颈的吞吐量，不要让它等待。
3. **让其他一切服从**约束。非瓶颈步骤应按瓶颈的节奏运行，而非按自身最大速度运行。
4. **提升**约束。如果充分利用仍不够，应投资提高瓶颈容量。
5. **重复。**解决一个瓶颈后会出现新瓶颈，应重新开始。

### 找到瓶颈

| 方法 | 做法 | 最适合 |
|--------|-----|----------|
| **走查流程** | 到工作发生的地方观察。哪里的在制品堆积最多？ | 快速评估、小型流程 |
| **容量分析** | 计算每个步骤的最大吞吐量。最低者 = 瓶颈。 | 制造、事务性流程 |
| **周期时间分析** | 测量每个步骤的实际时间。最长者 = 瓶颈。 | 知识工作、服务 |
| **队列** | 最长队列在哪里？队列之前的步骤就是瓶颈。 | 所有流程 |

### 瓶颈反模式

- **优化非瓶颈。**改进并非瓶颈的步骤，对整体容量的提升为 0%。它只会生成更多排队等待瓶颈处理的在制品。
- **让瓶颈闲置。**午休、会议、培训。如果瓶颈停止，整个系统都会损失吞吐量。保护瓶颈的时间。
- **忽略波动性。**某个步骤平均来看可能不像瓶颈，但如果波动性很高，就会造成间歇性瓶颈。

## 工作流优化模式

### 七种浪费（TIMWOOD）

| 浪费 | 说明 | 知识工作中的示例 |
|-------|-------------|--------------------------|
| **T**ransportation（运输） | 不必要地移动工作 | 团队之间多次交接 |
| **I**nventory（库存） | 过多在制品 | 未关闭工单过多 |
| **M**otion（动作） | 人员不必要地移动 | 上下文切换、寻找信息 |
| **W**aiting（等待） | 步骤之间的空闲时间 | 审批队列、评审积压 |
| **O**ver-processing（过度加工） | 做得超过需要 | 过度文档化、过度工程化 |
| **O**ver-production（过度生产） | 在需要之前完成工作 | 在没有需求时构建功能 |
| **D**efects（缺陷） | 需要返工的错误 | 缺陷、沟通错误、错误数据 |

### 流程改进启发式

| 启发式 | 适用场景 | 预期影响 |
|-----------|--------------|-----------------|
| 消除交接 | 流程有 5 次以上交接 | 高——每次交接都会增加延迟和错误 |
| 并行执行独立步骤 | 顺序步骤彼此不依赖 | 中高——显著缩短前置时间 |
| 提前做出决策 | 后期审批导致返工 | 高——尽早失败，而非延后失败 |
| 自动化验证 | 人工检查缓慢且不一致 | 中——对一致性的改善大于速度 |
| 标准化例外 | 同一例外每次采用不同方式处理 | 高——降低认知负荷和错误 |
| 缩小批量 | 大批量增加前置时间和波动性 | 中——流程更平稳，反馈更快速 |
| 移除签字层级 | 日常决策需要 3 次以上审批 | 高——审批带来延迟，而非质量 |
