# 供应商管理

供应商是合作伙伴，而不是一次性交易。管理良好的供应商关系能够降低风险、提高服务质量，并为成本谈判创造筹码。

## RFP 流程

Request for Proposal（RFP，征求建议书）是一种评估供应商选项的结构化流程。对于需要比较多个供应商的重大投资，应使用 RFP。

### RFP 生命周期

1. **需求定义**——供应商必须做什么？哪些属于锦上添花？
2. **供应商短名单**——选择 3-5 家能够满足需求的供应商
3. **发布 RFP**——向入围供应商发送正式文档
4. **供应商问答**——澄清问题，确保所有供应商获得相同信息
5. **建议评估**——根据加权准则为建议评分
6. **供应商演示/POC**——入围供应商展示能力
7. **客户参考访谈**——向现有客户核实
8. **谈判与选定**——确定最终条款并选定供应商

### RFP 模板

```
1. 高管摘要
   - 项目概述、时间线、预算范围

2. 公司背景
   - 公司介绍、我们的需求、当前状态

3. 工作范围
   - 详细需求（必须具备、应该具备、最好具备）
   - 可交付成果、里程碑、成功准则

4. 供应商资格要求
   - 公司规模、经验、认证
   - 安全与合规（SOC 2、ISO 27001、GDPR）
   - 所需客户参考

5. 商务条款
   - 要求的定价模型（按席位、固定价格、按使用量）
   - 合同期限、SLA 要求
   - 付款条款

6. 提交要求
   - 格式、截止日期、联系人
   - 供应商需回答的问题

7. 评估准则
   - 如何为建议评分
   - 每个维度的权重
```

### RFP 评估矩阵

| 准则 | 权重 | 供应商 A | 供应商 B | 供应商 C |
|-----------|--------|----------|----------|----------|
| 功能匹配度 | 25% | | | |
| 技术架构 | 15% | | | |
| 安全与合规 | 15% | | | |
| 总成本（3 年 TCO） | 20% | | | |
| 支持与服务 | 10% | | | |
| 公司稳定性 | 10% | | | |
| 客户参考 | 5% | | | |
| **总计** | **100%** | | | |

### RFP 反模式

- **为通用商品采购使用 RFP。**为每月 $500 的电子邮件工具发起 RFP 会浪费所有人的时间。RFP 应用于重大、战略性决策。
- **供应商过多。**全面评估 10 家供应商并不现实。限制在 3-5 家。
- **信息不平等。**一家供应商的问题得到回答，其他供应商却没有。应向所有供应商平等分享问答。
- **被需求清单拖垮。**包含 200 项的需求清单会掩盖重要需求。应区分必须具备和最好具备。

## SLA 设计

服务级别协议定义供应商保证什么，以及未达到保证时会发生什么。

### SLA 组成部分

| 组成部分 | 定义 | 示例 |
|-----------|-----------|---------|
| **服务定义** | 具体覆盖什么 | “核心平台 API 可用性” |
| **可用时间承诺** | 服务可用时间占比 | 99.9% 可用时间（不含计划维护） |
| **测量周期** | 如何计算可用性 | 月度平均值、季度调整 |
| **排除项** | 不覆盖什么 | 计划维护、不可抗力、客户侧问题 |
| **服务抵扣** | 未达到 SLA 的惩罚 | 每低于目标 0.1% 抵扣 5%，最高 25% |

### 抵扣结构

| 可用时间占比 | 抵扣（典型） |
|----------|------------------|
| 99.9-100% | 无抵扣 |
| 99.0-99.9% | 月费的 5% |
| 95.0-99.0% | 月费的 10% |
| < 95.0% | 月费的 25% + 解约权 |

### 超越可用时间：多维 SLA

| 维度 | 定义 | 典型目标 |
|-----------|-----------|---------------|
| **可用性** | 服务可以访问 | 99.9%（标准）、99.99%（关键） |
| **性能** | 响应时间处于阈值内 | P95 < 500ms |
| **支持响应** | 首次响应时间 | 严重：< 1 小时，高：< 4 小时，普通：< 24 小时 |
| **支持解决** | 解决时间 | 严重：< 4 小时，高：< 8 小时，普通：< 5 天 |

### SLA 陷阱

- **衡量容易测量的内容，而非重要内容。**仪表盘可用时间容易衡量，但 API P95 延迟、数据新鲜度和错误率更重要。
- **测量不透明。**如果无法独立验证可用时间，SLA 就无法执行。要求提供状态页面和月度报告。
- **无关痛痒的抵扣。**每月 $1K 合同的 5% 抵扣只有 $50，不足以激励表现。
- **忽略退出。**如果 SLA 违规不断累积，应有因故解约条款，并要求协助数据迁移。

## 供应商评分卡

评分卡持续评估供应商表现。应按季度复审，并将其纳入续约决策。

### 评分卡模板

| 类别 | 权重 | 指标 | 目标 | 实际 | 评分 |
|----------|--------|--------|--------|--------|-------|
| **服务质量** | 25% | 可用时间 SLA | 99.9% | | |
| | | 响应时间（P95） | < 500ms | | |
| **支持** | 20% | P1 响应时间 | < 1 小时 | | |
| | | 工单满意度 | > 4.0/5.0 | | |
| **安全** | 15% | SOC 2 有效 | 是 | | |
| | | 渗透测试结果 | 无严重发现 | | |
| **价值** | 20% | 相对预算的成本偏差 | < 5% | | |
| | | 相对路线图的功能交付 | 按计划 | | |
| **关系** | 10% | 高管互动 | 每季度 | | |
| | | 升级响应速度 | < 24 小时 | | |

### 供应商分层

| 层级 | 关键程度 | 管理节奏 | 退出计划 |
|------|-------------|-------------------|-----------|
| **第 1 层：战略性** | 业务运营的核心 | 月度复审、季度业务复盘、年度合同 | 持续维护，每半年更新 |
| **第 2 层：重要** | 重要但可替换 | 季度绩效复审 | 持续维护，每年复审 |
| **第 3 层：运营性** | 有用但非关键 | 年度复审 | 记录在案，但不作为活跃计划维护 |
| **第 4 层：通用商品** | 易于替换 | 通过 SOW 监控 | 无需正式退出计划 |

### 供应商评分卡陷阱

- **低分没有后果。**如果供应商持续低分却仍保有合同，评分卡只是表演。将评分卡与续约决策关联。
- **所有供应商都每年复审。**年度复审对关键供应商频率太低，对通用商品供应商又太高。让节奏与关键程度匹配。
- **只评分，不沟通。**不要只发送评分卡。与供应商共同复审；他们对数据的反应与数据本身同样有信息价值。

## 供应商管理启发式

| 启发式 | 原因 |
|-----------|-----|
| **绝不要成为供应商唯一的客户。** | 如果供应商倒闭，你会陷入困境。 |
| **始终制定退出计划。** | 无法切换时，切换成本最高。签约前了解退出成本。 |
| **数据可移植性不可协商。** | 确保随时可以用标准格式导出数据。 |
| **签约前谈妥续约。** | 了解续约流程和升级结构。销售期间乐于帮助的供应商，在续约时可能变得对立。 |
| **供应商集中度就是风险。** | 如果一家供应商承担某项能力的 30% 以上，就存在集中风险。识别替代方案。 |
| **最便宜的选项很少真正最便宜。** | 隐性成本（集成、培训、变通方案）会让便宜的供应商变昂贵。计算真实 TCO。 |
| **多年期合同需要价格保护。** | 锁定价格或年度最高涨幅。没有保护，就只能任由供应商定价。 |
