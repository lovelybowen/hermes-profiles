# 产物金字塔：框架与对称性

## 核心洞见

渐进披露规定如何向 AI Agent 提供上下文：从元数据（约 100 个 token）开始，激活时扩展为指令（少于 5000 个 token），再按需加载资源。**产物金字塔把同一原则应用到 Agent 的产出。**

无论 Agent 正在阅读技能说明还是研究产物，均受相同约束，即有限上下文窗口和过载导致的非线性质量退化。无论 Agent 加载程序性知识还是接收陈述性发现，同一解决方案都适用，即由可按需加载、相互链接的分层单元实现渐进披露。

## 不对称问题

在当前 AI Agent 工作流中：

| | 输入侧 | 输出侧 |
|---|---|---|
| 结构 | 渐进披露（3 层） | 单一扁平文档 |
| 消费方式 | 仅加载所需内容 | 一切内容被捆绑在一起 |
| 成本 | 50 个技能约有 2500 个 token 开销 | 每个使用方占用完整上下文窗口 |

多 Agent 管线中的每个 Agent 都会继承上游 Agent 的上下文。没有金字塔时，上下文会在各阶段累积，最终每个下游 Agent 都在被与其特定角色无关材料污染的窗口中工作。

## 对称性

| 输入层级（技能加载） | 输出层级（产物金字塔） |
|---|---|
| **元数据：**名称 + 描述（约 100 个 token） | **L1 摘要：**关键发现、影响（入口） |
| **指令：**激活时加载完整技能正文 | **L2 分析集合：**按维度拆分文件 |
| **资源：**按需加载参考文件 | **L3 详细档案：**来源摘录、访谈记录 |

对称性是核心架构洞见：相同的三层模型、相同的上下文经济纪律，应用于 Agent 写出的内容，而非读入的内容。

## 与其他框架的关系

### DIKW 金字塔（Ackoff 1989）

| DIKW | 产物金字塔 |
|---|---|
| 智慧 | L1 摘要（可行动的洞见、决策） |
| 知识 | L2 分析集合（关联的理解） |
| 信息 | L3 详细档案（提取的数据点） |
| 数据 | 原始一手来源（未处理的采集内容） |

### Agent Skills（agentskills.io）

产物金字塔是向外映射的 Agent Skills 模型：

```
Skill File:     SKILL.md (metadata) → SKILL.md body (instructions) → references/ (resources)
     ↓ mirror
Artifact:       L1 Summary (metadata) → L2 Analysis (instructions) → L3 Dossiers (resources)
```

## 多 Agent 路由

金字塔为 orchestrator 提供精确性，使其只交付每个下游角色所需的内容：

| Agent 角色 | 接收内容 |
|---|---|
| 产品经理 Agent | 仅 L1 摘要 |
| 市场分析师 Agent | 特定 L2 分析文件 |
| 数据架构师 Agent | L3 档案 |
| 验证 Agent | L3 档案加 L2 文件 |

这避免了上下文累积问题：每个 Agent 只获得它实际需要的内容。

## 金字塔失效的场景

1. **临时输出：**一次性计算不需要三层。
2. **来源即输出：**只收集数据而不综合，会使金字塔坍缩。
3. **仅一个使用方：**同一 Agent 同时消费和产生内容时，结构化交接的开销可能不值得。
4. **极小输出：**三句话的回答不需要三层。

适用金字塔的情形：研究深度超过 5 个来源、涉及多 Agent 交接，或输出需要可审计和可复用。
