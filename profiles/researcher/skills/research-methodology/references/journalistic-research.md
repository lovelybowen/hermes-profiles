# 新闻调查研究路径

适用于来源密集、叙事驱动的调查型内容，其中事实必须经受公开审视。

## 与学术研究的核心差异

学术研究假定所有来源均已公开且可检索。新闻调查研究则假定最佳来源是人、原本不打算公开的文件，以及研究者亲自作出的观察。证据更加杂乱，验证负担更高，出错的后果也更直接。

## 一手来源处理

### 新闻证据层级

| 层级 | 来源类型 | 处理方式 |
|------|-------------|-----------------|
| 1 | **一手文件** - 邮件、内部备忘录、法庭文件、财务报表、代码提交、泄露数据 | 权重最高。先验证真实性，再将文件所述内容视为事实依据 |
| 2 | **亲历证词** - 在场、目击事件或亲自完成相关事项的人 | 具名来源强于匿名来源；可能时用文件佐证具体细节 |
| 3 | **同期记录** - 会议纪要、聊天记录、当时制作的录音 | 强于记忆，数周后记忆已经不可靠 |
| 4 | **已发布报道** - 报道过该事件的其他记者 | 应引用，不要将其工作重新报道；若依赖其报道，必须明确说明 |
| 5 | **二手说法** - 从当事人处听说的人 | 最弱层级。仅在一手来源不可得且转述链很短时使用 |

### 具名来源标准

**始终优先具名来源。**被证明错误的具名来源会损害你的可信度；被证明正确的匿名来源同样会损害可信度，因为读者无法验证发言者是谁。

来源要求匿名时：

1. **确认原因。**是害怕报复、受保密协议约束，还是不愿公开署名？原因决定信息权重。
2. **了解其身份。**读者可以不知道，但你必须知道并记录。即使读者无法验证，来源对你也必须可验证。
3. **佐证其主张。**提出可验证主张的匿名来源有价值；提出不可验证主张的匿名来源只是传闻。
4. **绝不向未直接交谈过的来源承诺匿名。**二手匿名说法不是来源。
5. **披露能够披露的内容。**“一名因无权讨论内部事项而要求匿名的现任员工”优于“消息人士称”。

### 访谈完整性

- **记录谈话。**始终先征得许可。如果对方拒绝，做同期笔记，并在访谈中复述关键引语以确认。
- **验证身份。**如之前未见过此人，在将其信息作为来源前验证身份。可以使用 LinkedIn、公司网站并与其他人交叉核验。
- **上下文很重要。**对方发言时还发生了什么？在何种情况下分享信息？愤怒的来源可能夸大，恐惧的来源可能淡化。
- **后续跟进。**最好的引语常出现在关闭录音设备后，或者对方有时间思考后的第二次谈话中。

## 文件调查

并非所有有价值的证据都来自人。有些最佳来源是显而易见的公开文件。

### 值得寻找的文件类型

| 文件类型 | 观察重点 | 获取位置 |
|--------------|-----------------|------------------|
| **Git 历史** | 功能何时添加？谁提交？提交说明是什么？是否经过评审？ | GitHub、git log、PR 讨论 |
| **财报记录** | 管理层实际如何谈论战略？与其行为对比 | SEC.gov、投资者关系页面、财报电话会记录 |
| **招聘信息** | 正在招聘哪些技能？职位描述揭示哪些优先事项或问题？ | 公司招聘页面、LinkedIn |
| **支持论坛** | 用户实际遇到什么困难？形成了哪些变通方法？ | GitHub issues、社区论坛、subreddits |
| **变更日志** | 产品六个月前与现在分别是什么样？哪些功能被移除？ | 变更日志存档、Wayback Machine |
| **申报或管线文件** | SEC 文件、专利申请、监管申报 | EDGAR、专利数据库、FCC 文件 |

### 带着问题阅读

不要只是阅读文件，而应对它提出问题：

- **谁创建了它，为什么？**每份文件都有目标受众和目的。新闻稿旨在展示公司形象，内部备忘录用于传达运营方向，专利申请用于主张法律权利。
- **缺少什么？**缺失往往比出现的内容更有揭示性。安全审计未提及认证是一项发现；新闻稿未提及 CEO 是一个信号。
- **依赖什么假设？**“第四季度收入同比增长 15%”假设上一年第四季度是合适基线。如果该季度发生了收购呢？
- **标题与正文是否一致？**新闻稿、博客文章和报告的标题经常夸大正文发现。不要止步于导语。

## 三来源规则（新闻版）

针对以下事实性主张：
- 指控某人有不当行为。
- 依赖令人意外的统计数据。
- 被其他来源质疑。
- 如有错误会造成损害。

**必须拥有三个独立来源。**不是三篇互相引用的文章，而是不同的人、不同文件、不同方法论得出的三个真正独立来源，且都指向同一事实。

如果无法获得三个来源，应报告置信度缺口：“只有一名直接知情者愿意谈论此事，但其陈述与[出版物]审阅的内部文件一致。”

## 系列内容中的研究

研究五篇系列中的第三篇时，陷阱是重复研究已经确立的内容。

### 单篇研究地图

For each article in a series:

| 维度 | 早期篇章已完成内容 | 本篇需要研究的内容 |
|-----------|---------------------------|----------------------------|
| **共享上下文** | 读者从第 1 至 2 篇已知的内容 | 本篇需要什么新上下文？ |
| **需要重访的来源** | 早期提供过重要信息的专家 | 是否存在值得后续访谈的新角度？ |
| **需要更新的主张** | 早期篇章确立的事实 | 发布后是否发生变化？ |
| **反复出现的人物** | 早期篇章介绍的人 | 是否出现在本篇？是否需要重新介绍？ |
| **主题主线** | 迄今连接整个系列的主题 | 本篇是推进、复杂化还是分叉？ |

### 系列简报

开始研究新篇章前，写一段“当前进展”摘要，回答：
1. 系列迄今已经确定了什么？
2. 早期篇章遗留哪些开放问题？
3. 本篇覆盖哪些新领域？
4. 早期篇章中的哪些来源可以讨论这些新领域？

这可以避免重复研究，并使每篇内容建立在上一篇之上。

## 发布前验证协议

发布任何具有调查风险的内容前：

1. **逐字对照来源阅读草稿中的每条引语。**不要凭记忆，应以录音或笔记为准。
2. **打开草稿中的每个链接。**来源是否表达了草稿所称的内容？数字是否一致？引语是否准确？
3. **三角验证每个意外主张。**如果发现会改变读者认知，至少需要两个来源。
4. **检查时效性。**快速变化技术中，称为“当前”的统计数据应在两年以内；较慢领域为五年以内。明确标注过时数据。
5. **审计转述漂移。**草稿可能准确引用来源却夸大主张强度。论文说“表明”时，不应转述为“证明”。
6. **标记单一来源主张。**任何仅依赖一个来源的主张都应在草稿中指出，读者有权了解证据基础。
7. **执行“如果我错了”测试。**假设文章中的所有主张都被证明错误，哪些损害最大？对它们进行最严格验证。
