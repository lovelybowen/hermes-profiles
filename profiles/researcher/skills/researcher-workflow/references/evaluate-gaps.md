# 评估缺口

## 使用时机

完成阶段 2（收集）后加载此技能。此时研究日志已经记录发现、来源和缺口。本阶段判断是否需要新一轮研究，或是否可以开始构建金字塔。

## 执行步骤

### 1. 读取当前状态

读取范围文档和最新研究日志，了解已有内容和缺失信息。

### 2. 应用三问模型

针对研究日志中记录的每个缺口，提出以下问题：

**Q1：此缺口是否在范围内？**
缺失信息是否位于任务简报定义的范围边界内？如果在范围外，记录但不要继续调查；如果在范围内，进入 Q2。

**Q2：补齐此缺口是否会改变结论？**
如果获得这个缺口的答案，是否会实质改变计划报告的发现？如果只会增加细节而不会改变整体判断，则优先级较低；如果会改变结论，则优先级较高。

**Q3：增加的是深度，还是只增加材料数量？**
继续调查此缺口会增加新的理解维度（深度），还是只会堆积更多同类证据（数量）？深度会产生复合价值，单纯增加数量则会稀释重点。值得为深度开展新一轮调查，不值得为数量这样做。

### 3. 作出递归决策

| 情形 | 决策 |
|---------|----------|
| 缺口在范围内、会改变结论且增加深度 | **递归** - 完整或定向调查 |
| 缺口在范围内、不改变结论但增加深度 | **递归** - 轻量调查（仅搜索） |
| 缺口在范围内、不改变结论且只增加材料数量 | **停止** - 记录缺口以保持透明 |
| 缺口在范围外 | **停止** - 记录为范围外事项 |

### 4. 确定递归强度

如果决定递归，选择合适的强度：

- **轻量**（1 至 2 次快速搜索）：`web_search "<specific query>"`
- **定向**（需要一篇文章或一个来源）：`web_extract <url>`
- **完整调查**（需要探索大量新领域）：多篇 `web_extract` + `synthesis-patterns.md` 综合方法（若环境可用，`groktocrawl agent` 可加速）
- **需要浏览器**（疑似由 JS 渲染内容）：browser 工具套件

工具选择与回退链见 `references/tool-governance.md`。

### 5. 执行或推进

如果递归：携带针对特定缺口的聚焦任务返回阶段 2（收集），并编写缺口简报：

```markdown
# 缺口简报：<缺口说明>

## 所需信息
<后续调查需要回答的具体问题>

## 重要性
<它与 Q2 的关系，即会如何改变结论>

## 建议方法
<轻量/定向/完整调查/浏览器>
```

将其保存为 `<artifacts-root>/<mission-slug>/layer-3-detailed/gap-brief-<N>.md`，并确保该文件在交付时被声明为产物（Kanban 任务走 `kanban_complete(artifacts=[...])`）。

递归调查后再次评估缺口。允许进行第二轮递归；第三轮递归必须有充分理由，此时应考虑范围本身是否过于宽泛。

如果不递归：进入阶段 4（构建金字塔）。

## 转换信号

- **如果递归：** 携带缺口简报返回阶段 2（收集）。
- **如果停止：** 进入阶段 4（构建金字塔），全部已收集材料均位于 `layer-3-detailed/`。

## 保存内容

每轮评估都生成一份缺口简报和递归决策。保存这些内容，使金字塔可以引用经过明确判断后搁置的事项。
