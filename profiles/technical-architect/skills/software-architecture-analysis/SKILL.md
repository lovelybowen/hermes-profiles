# 软件架构分析 - 从代码库逆向分析到设计文档

## 使用时机

- 已有参考实现，需要理解其架构以获得设计启发。
- 需要为同一问题领域中的系统编写 PRD、设计文档或规范。
- 输出必须采用**洁净室**方式：不从参考代码库复制任何源代码示例。
- 所设计系统的架构约束与参考实现不同，例如本地优先、隐私优先或自托管。
- 需要提取代码库执行的存储操作这一**隐式契约**，以设计正式的提供者抽象。

**不适用于：**直接代码评审、缺陷排查或安全审计，此类任务应使用专门的调试技能；也不适用于简单的工具或库评估，此类任务应开展技术探针。

## 构建工作流

```
阶段 1：克隆并绘制结构 → 阶段 2：查找关键文件 → 阶段 3：绘制架构
                                                              ↓
阶段 6：按约束重新设计 ← 阶段 5：编写规范 ← 阶段 4：功能清单
                                                              ↓
                                                      阶段 7：QA
```

## 阶段索引

| 阶段 | 产物 | 何时进入 |
|---|---|---|
| 1 克隆并绘制结构 | 顶层目录结构 + 各目录的语言/角色判定 | 任务开始 |
| 2 识别关键架构文件 | 按行数排序的 15–25 个核心文件清单 | 阶段 1 完成 |
| 3 绘制架构 | 采集/处理/存储/外部依赖/隐私状况 + Mermaid 图 | 阶段 2 完成 |
| 3b 接口提取模式 | 提供者抽象 / DAO 契约（仅提取隐式契约时） | 目标是存储契约时替代阶段 4–5 |
| 4 功能范围清单 | 按采集/处理/AI/存储/集成/插件分组的用户功能 | 阶段 3 完成 |
| 5 编写洁净室规范 | 设计文档 / PRD | 阶段 4 完成 |
| 6 改变约束重新设计 | 本地优先 / 隐私优先的替代方案与开放标准 | 有需要替换的约束时 |
| 7 交付后 QA | 链接、图表、污染、交叉引用的检查结果 | 文档交付后 |

完整步骤、命令与示例见 `references/reverse-engineering-workflow.md`。

## 必须记住的约束

- **洁净室：**绝不复制参考实现的源代码片段；规范面向*新代码*，不是衍生作品。若输出含可辨认来自参考实现的代码模式，在更高抽象层级重写。
- **图表只用 Mermaid：**所有图表代码块必须是 ` ```mermaid `，不使用 ASCII 方框图或图像文件；每条管线独立一张图，不合并成单体图。
- **阶段 5 是最关键的阶段。**按架构层级引用原始代码库，不使用行号或变量名。
- **外部依赖要给出开放标准替代方案**（例如“兼容 OpenAI 的 API，因此可使用任意提供商”）。
