# API 集成

## API 客户端设计

| 层级 | 职责 |
|-------|---------------|
| 客户端实例 | 基础 URL、默认请求头、超时、拦截器 |
| 请求拦截器 | 注入认证令牌、请求日志、请求 ID |
| 响应拦截器 | 401 时刷新令牌、规范化错误、响应日志 |
| 服务模块 | 每个领域的类型化 API 方法、请求/响应转换 |
| Hook 层 | 带加载/错误/空状态的数据获取 Hook |

## 认证令牌流

```
登录 → 存储令牌 → 附加到请求 → 检测过期 → 刷新 → 重试
                                               ↓
                                         刷新失败时重新登录
```

| 存储位置 | 优点 | 缺点 |
|-----------------|------|------|
| HTTP-only cookie | 可抵御 XSS | 存在 CSRF 风险，SPA 较难读取 |
| 内存（变量） | 最安全，不持久化 | 刷新页面后丢失 |
| localStorage | 刷新后保留，简单 | 页面上的任意 JS 均可访问 |
| Session storage | 同一标签页刷新后保留 | 关闭标签页后清除 |

## 实时更新

| 协议 | 使用时机 | 连接管理 |
|----------|-------------|---------------------|
| WebSocket | 双向、低延迟 | 带退避的重连、心跳、回退到轮询 |
| SSE（Server-Sent Events） | 仅服务端到客户端，比 WebSocket 简单 | 自动重连、使用事件 ID 恢复 |
| 短轮询 | 简单，不支持服务端推送 | 固定间隔，空闲时浪费资源 |
| 长轮询 | WebSocket/SSE 不可用时 | 持久连接、超时处理复杂 |
