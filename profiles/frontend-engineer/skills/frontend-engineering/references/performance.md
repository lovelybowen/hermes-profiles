# 客户端性能

## Core Web Vitals 目标

| 指标 | 良好 | 需要改进 | 差 |
|--------|------|-------------------|------|
| LCP（最大内容绘制） | ≤ 2.5 秒 | 2.5 秒 - 4.0 秒 | > 4.0 秒 |
| FID（首次输入延迟）/ INP | ≤ 100 毫秒 | 100 毫秒 - 300 毫秒 | > 300 毫秒 |
| CLS（累计布局偏移） | ≤ 0.1 | 0.1 - 0.25 | > 0.25 |

## 构建产物优化

| 技术 | 影响 | 工作量 |
|-----------|--------|--------|
| 按路由代码拆分 | 高 | 低，多数框架内置 |
| 为重型组件使用动态导入 | 中 | 低 |
| 摇树优化未使用导出 | 中 | 低，打包器默认启用 |
| 关注导入成本 | 中 | 中，需要 lint 规则和 CI 检查 |
| 图像优化，例如格式、尺寸、延迟加载 | 高 | 中 |
| 依赖审计，删除未使用依赖并寻找轻量替代项 | 中 | 高 |

## 渲染优化

| 模式 | 使用时机 | 机制 |
|---------|-------------|-----------|
| 记忆化 | 经常重新渲染的纯组件 | `React.memo`、`useMemo`、`useCallback` |
| 虚拟化 | 长列表，1000 项以上 | `react-window`、`react-virtuoso` |
| 防抖 | 高频事件，例如搜索输入、滚动 | 防抖 300-500 毫秒 |
| 节流 | 受频率限制的更新，例如调整尺寸、滚动位置 | 节流 100-200 毫秒 |
| 渐进水合 | 首屏以下的重型交互内容 | 可见时延迟水合 |
