# 流水线阶段：三个层级详解

## 层级编号约定

产物金字塔按**自顶向下**的方式为层级编号，与 Agent Skills 输入模型一致：

| | Agent Skills（输入） | 产物金字塔（输出） |
|---|---|---|
| 第 1 层 | 技能元数据（约 100 tokens） | **摘要**——入口点，提炼程度最高 |
| 第 2 层 | 技能指令（少于 5000 tokens） | **分析集合**——按需提供细节 |
| 第 3 层 | 参考文件（按需加载） | **详细档案**——完整证据基础 |

### 第 0 层：不生成金字塔（证据档 L0）

并非所有任务都需要金字塔。当任务类型为 T0/T1、改动单文件且 ≤30 行无依赖，或产出本身就是状态、阻断、澄清与审批请求时，证据档位为 **L0**：不创建 `00-index.md`，不创建任何层级目录，只返回结构化交接消息（`status` / `summary` / `evidence` / `risks`）。

这不是「精简的金字塔」，而是**没有金字塔**：为零散的中间态强行建目录会制造空层和悬空 `SOURCES`。L0 的最低证据强度与各档位升级触发器见 `evidence-levels-and-seb.md`。

## 第 1 层：摘要

### 目的
所有使用方 Agent 的入口点。用一份文件陈述研究问题、关键发现和最重要的影响。不包含证据、方法论或支撑数据——这些内容位于下一层。

### 格式
一份 Markdown 文件，通常为几段到几页。

### 内容
- 研究问题（根据任务简报重新陈述）
- 关键发现（3-5 个要点或短段落）
- 影响（这对受众意味着什么）
- 底部的 **SOURCES 部分**，链接到第 2 层分析文件：

```
SOURCES (LAYER 2 NAVIGATION)
research/analysis/market-position.md
 -> 竞争对手映射和市场份额分析

research/analysis/technical-feasibility.md
 -> 架构评估
```

### 使用者
- 业务决策者（关注战略方向，无需技术深度）
- 高管（标题级决策）
- 判断是否需要深入阅读的快速浏览者

### 质量门（Gate A）

- [ ] 摘要中的每项主张都链接到一份具体的第 2 层分析文件
- [ ] 摘要不包含无支撑的断言——所有内容都可向下追溯
- [ ] 摘要可独立使用（不阅读下层也能理解）
- [ ] 明确陈述影响，不将其埋在发现中

---

## 第 2 层：分析集合

### 目的
可独立使用的分析文件，每份覆盖研究的一个具体维度。只需要一个维度的使用者仅加载该文件，无需加载其他内容。

### 格式
独立的 Markdown 文件，每个研究维度一份。每份文件都可独立使用。

### 典型维度
- 市场分析（规模、趋势、细分）
- 竞争格局（定位、优势、缺口）
- 技术可行性（架构、约束、取舍）
- 风险评估（不确定性、故障模式、缓解措施）
- 监管分析（合规、司法管辖问题）

### 内容
- 此维度的论点或研究问题
- 带支撑证据的分析叙述
- 按需提供数据可视化或表格
- 底部的 **SOURCES 部分**，链接到第 3 层档案：

```
SOURCES (LAYER 3 NAVIGATION)
research/dossiers/competitor-profiles.md
 -> 各市场的竞争定位数据

research/dossiers/interview-transcripts.md
 -> 第 2 节引用的客户访谈记录
```

### 使用者
- 领域专业 Agent（数据科学家只读取数据分析）
- 深度研究人员（需要一个维度，而非完整全貌）
- 编写跨领域综合的下游 Agent

### 质量门（Gate B）

- [ ] 每份分析文件都可独立使用（不读取周边文件也能理解）
- [ ] 每项主张都可追溯到具体的第 3 层来源
- [ ] 分析在原始数据基础上增加了解释价值
- [ ] 明确呈现相互冲突的证据，不将其掩埋
- [ ] 第 3 层导航（SOURCES）完整

---

## 第 3 层：详细档案

### 目的
范围最广的层级。包含来源摘录、原始数据表、访谈记录和方法论说明。它是供使用方 Agent 按需读取的参考资料库——并非用于线性阅读。

### 格式
多种类型的文件：Markdown 笔记、原始数据导出、捕获的页面、访谈摘录。

### 典型内容
- 来源摘录（附有来源元数据）
- 原始数据表
- 访谈或会议记录
- 方法论文档
- 文献综述笔记
- 数据集说明

### 使用者
- 验证者（事实核查上层主张）
- 深度研究人员（需要完整证据基础）
- 下游分析工具（嵌入流水线、图数据库）

### 质量门（Gate C）

- [ ] 每个来源均有出处信息（URL、时间戳、作者、标题）
- [ ] 摘录忠实于原文（没有歪曲）
- [ ] 方法论已有记录（数据如何收集/处理？）
- [ ] 档案组织方式便于发现（不是原始内容倾倒）

## 生成流程：如何构建金字塔

金字塔不是研究完成后套用的格式模板，而是递归研究方法论的自然输出：

```
任务简报
  ↓
1. 任务推演
   将简报重构为明确的研究问题、
   范围边界和已知未知项登记表。
  ↓
2. 系统化收集
   所有来源收集均使用 groktocrawl——单个 URL 使用 scrape，发现信息使用 search，综合使用 agent。
   捕获来源、提取证据，并组织成
   第 3 层档案的初稿。
  ↓
3. 起草第 2 层分析
   根据档案编写按维度拆分的分析文件。
   添加链接回档案的 SOURCES 部分。
  ↓
4. 起草第 1 层摘要
   根据分析文件编写摘要。添加链接到
   分析文件的 SOURCES 部分。
  ↓
5. 缺口评估
   对每个缺口进行评估：它是否在范围内？填补它是否会
   改变上层中的任何结论？它是增加深度，
   还是只增加体量？
  ↓
6. 递归（如需要）
   深入处理未解决缺口。随着新证据到来更新各层。
  ↓
发布
```

关键洞察：**深度取决于任务复杂度，而不是固定模板。**一份简单的技术说明简报可能只生成摘要和两份分析文件。竞争格局分析则可能需要全部三个层级，并且每层包含多份文件。

## 跨层导航

### 显式 SOURCES 格式

每个文件底部都包含以下内容：

```
SOURCES (LAYER {N} NAVIGATION)
path/to/file.md
 -> 一行说明，回答“如果继续深入，我会看到什么？”

path/to/another-file.md
 -> 另一个维度或支撑证据
```

### 使用流程

```
L1 摘要
  ↓ 读取 SOURCES，仅加载所需分析
L2 market-position.md
  ↓ 读取 SOURCES，加载档案以验证主张
L3 competitor-profiles.md
```

### 生成流程

```
L3 来源采集
  ↓ 编写分析
L2 分析集合
  ↓ 综合发现
L1 摘要
```

### 审计

1. **正向审计**：从档案开始 → 每个来源均有效 → 分析可靠 → 摘要可信。
2. **反向审计**：从摘要开始 → 为每项主张找到 L2 文件 → 为 L2 中的每项主张找到 L3 档案 → 验证每个来源。
