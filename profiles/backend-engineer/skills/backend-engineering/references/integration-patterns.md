# 集成模式

## 外部调用韧性

| 模式 | 防护对象 | 实现方式 |
|---------|------------------------|----------------|
| 带退避的重试 | 瞬时失败 | 指数退避加抖动，限制最大重试次数 |
| 熔断器 | 持续失败 | N 次失败后打开，超时后半开 |
| 超时 | 挂起连接 | 每项操作设置连接、读取和写入超时 |
| 舱壁 | 级联失败 | 每个依赖使用独立线程池或连接池 |
| 幂等键 | 重复请求 | 客户端生成键，服务端去重 |

## 幂等键模式

```http
POST /api/payments
Idempotency-Key: 7c3d5e8f-a1b2-4c3d-8e5f-6a7b8c9d0e1f
```

| 方面 | 设计 |
|--------|--------|
| 键生成 | 客户端 UUID v4 |
| 存储 | 带 TTL（24 小时）的键值存储 |
| 首次请求 | 正常处理，按幂等键保存结果 |
| 重复请求 | 返回已保存结果，不产生副作用 |
| 过期键 | 作为新请求处理 |
| 进行中的请求 | 返回 409 Conflict |

## Webhook 验证

| 机制 | 验证内容 | 实现方式 |
|-----------|-----------------|----------------|
| HMAC 签名 | 载荷完整性、发送者真实性 | 共享密钥 → 对请求体计算 HMAC → 比较请求头 |
| Webhook 密钥 | 发送者身份 | 预共享密钥，定期轮换 |
| 时间戳新鲜度 | 防重放 | 拒绝早于 N 分钟的 webhook |

## 消息队列消费者模式

| 模式 | 使用时机 |
|---------|-------------|
| 至少一次投递 | 默认方式，需要幂等处理 |
| 恰好一次（去重） | 无法接受重复时，需要去重存储 |
| 批处理 | 高吞吐、可容忍延迟 |
| 死信队列 | 超过最大重试次数仍无法处理的消息 |

每个消费者都应在处理后确认、瞬时失败时重试、永久失败时进入 DLQ，并在每个阶段记录日志。
